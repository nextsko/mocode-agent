# 项目文档 & 计划目录规范（docs-rulebook，精简版）

在任何项目里建文档、写计划、归档文档时，按以下约定执行。核心一句话：**活跃的进活动区，完成的进归档区，临时笔记进草稿区，三区不混。** 目标仓库若已有自己的文档约定，先遵循仓库现状。

## 生命周期三区（默认命名）

- 活动区 `docs/in/`：活跃计划 + 活跃支撑笔记，只放进行中的东西。
- 归档区 `docs/plan/`（或 `docs/archive/`）：已完成/历史计划，只作历史参考；任务未明确要求不得照它执行。
- 草稿区 `docs/experiment/`、`docs/dev/`：临时探索笔记，简短、实用、可丢弃。

## 新建主题目录：`<docs-root>/<topic>/`

- topic 用短 kebab-case；版本化主题加 `-v1` 后缀（如 `request-context-bloat-v1`）；纯审计/调研类可不带版本号。
- 主题根必放 `README.md`；支撑笔记用 `NN-标题.md` 编号（标题用团队惯用语言），一个文档一个主题，范围跑偏就拆分。
- 多阶段大主题在主题根放 `MASTER_PLAN.md`，含量化验收目标与实施进度。
- 辅助产物分目录：`artifacts/`（按日期归档证据）、`specs/`、`interfaces/`、`logs/`、`scripts/`。

## 计划文件

- 位置：`<docs-root>/<topic>/plans/NN-short-purpose-plan.md`
- 命名：两位数序号 + 短连字符用途 + `-plan` 后缀；插入序号可用 `01b`。
- 文件头部固定元信息块：状态、创建日期、范围/目标、依赖（前置计划）、证据（数据/报告引用）、触达模块。

## 完成即归档

- 计划完成后从活动区移入归档区（或进版本忽略的存储）；禁止 finished plans 与 active docs 混放。

## 变更纪律

- 影响架构/边界的变更，同一变更里同步更新相关活跃计划文档 + 对应测试/护栏。
- Truth 顺序：项目结构清单（`go.mod` / `Cargo.toml` / `package.json` 等）→ 活动区计划 → 测试与护栏 → 公开 API/文档；README 与代码冲突时以这几处为准。
