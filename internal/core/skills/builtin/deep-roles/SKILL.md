# deep-roles：专家角色激活

## 概述

把「扮演某个专家」变成一次**显式角色激活**：先按路由表读取对应人设原文，再以该角色的职责、方法与输出格式工作。

这是一个**索引层** skill：它不复制人设内容，只负责路由到人设文件。人设文件才包含完整的职责、方法与输出格式。

## 何时使用

- 用户说「激活小安」「激活领域小安」
- 用户要求「以深度调试专家 / 深度调研专家 / 学习者身份」工作
- 场景属于：长篇多轮自主规划、系统性调试、深度调研、学习式讲解
- 调试场景可与 `bug-lesson`（踩坑检索）叠加使用

## 路由表

按角色读取对应人设原文，进入人设（默认根目录 `/data/fromsko/kng/`）：

| 角色 | 适用场景 | 先读原文 |
|------|----------|----------|
| 小安（自主计划专家） | 多轮、多计划的自主推进 | `commands/activate-xiaoan.md` |
| 领域小安（领域专家 + ask_user 计划内交互） | 需要领域专长并在计划内与用户交互 | `commands/activate-domain-xiaoan.md` |
| 深度调试专家 | 系统性调试、根因定位 | `exps/roles/debugger.md` |
| 深度调研专家 | 深度调研、材料综合 | `exps/roles/deep-researcher.md` |
| 深度学习专家 | 学习式讲解、由浅入深 | `exps/roles/learner.md` |

## 激活流程

1. **识别角色**：从用户措辞判断应激活哪个角色；含糊时向用户确认，不要自行混合人设。
2. **读取原文**：按路由表读取对应人设文件，以原文为准，不凭记忆复述。
3. **进入人设**：按人设定义的职责、方法与输出格式工作。
4. **保持基础规则**：角色文件只定义职责与方法，**不覆盖基础协作规则**——工具使用、安全边界仍按系统规则执行。
5. **必要时叠加**：调试场景叠加 `bug-lesson` 的踩坑检索与回归测试纪律。

## 约定

- 人设文件是**唯一权威来源**；本 skill 只做索引与路由，不替代人设。
- 角色切换应在多轮任务开始时明确一次，避免中途漂移。
- 计划内的用户交互（ask_user 类）遵循知识库中的交互模式（`knowledge/patterns/023-ask_user-节点-计划内用户交互.md`）。
- 角色只改变工作方法与输出风格，不改变事实准确性要求：任何完成 / 修复声明仍须遵守 `verification-before-completion`。

## Checklist

- [ ] 已识别目标角色，含糊处已向用户确认
- [ ] 已读取对应人设原文，而非凭记忆扮演
- [ ] 输出格式与职责与人设一致
- [ ] 未用角色设定覆盖系统的基础协作与安全规则
- [ ] 调试场景已叠加 `bug-lesson`
- [ ] 角色只改变方法/风格，未放宽证据要求

## 相关技能

- `bug-lesson`：调试场景的踩坑检索与回归测试闭环。
- `systematic-debugging` / `investigate-first`：深度调试专家的底层调查纪律。
- `verification-before-completion`：任何角色下的完成声明都需证据。
- `writing-plans` / `writing-skills`：自主规划类角色产出计划与技能时的写作纪律。
